# docs-ref-map.txt
#
# Reference map for the macros/mixer docs restructure (FRO179/FRO180).
#
# Format: one row per DISTINCT old-reference form found anywhere in the repo on this branch,
# tab-separated:
#
#   <old-ref>	<new-ref>
#
# <old-ref> is the old doc path (docs/<name>.md, as deleted by this branch's first commit) plus
# whatever section/item suffix actually appears attached to it in citing code/docs/tests/scripts
# (e.g. "docs/mixer.md §5.7", "docs/macros_implementation.md §7 item 6.1"). Trailing descriptive
# words a citation adds after the number ("note", "'s own requirement", "'s fix note") are folded
# into the base row UNLESS the described content lives under a genuinely different new heading,
# in which case it gets its own row with the same old-ref text plus that trailing description, so
# the two rows stay distinguishable.
#
# <new-ref> is always the full gated form docs/<path>.md#<anchor>, where <anchor> is the real
# GitHub slug of a heading that EXISTS in the new file (lowercase, spaces -> hyphens, punctuation
# dropped, a "/" with a space on each side collapses to a double hyphen). Where the whole new doc
# is the topic and no finer anchor is warranted (the old section was promoted wholesale into its
# own dedicated file with many subheadings, and citations carry no finer sub-number to key off),
# the bare path with NO anchor is used instead and the row carries a trailing "# ..." comment
# explaining why.
#
# A later relink stage consumes this file to rewrite every citation in place; it is the only
# thing this ticket is expected to produce — the docs themselves and their content are already
# final and are NOT to be edited as part of building this map.
#
# Old file -> current worktree location (all seven deleted by this branch, see 5d7276e for the
# pre-restructure content):
#   docs/macros.md               -> docs/macros/macros.md, docs/macros/ports.md,

#                                    docs/macros/macros.md

#   docs/mixer_implementation.md  -> docs/mixer/mixer.md, docs/mixer/panel.md,

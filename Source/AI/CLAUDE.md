# AI & trust-boundary invariants (Source/AI/)

The two rules stated in full in the root `CLAUDE.md` — never relax `validatePatch`, and `trusted=true` is about parameter fidelity — govern everything here. Mechanism and history live in [`docs/ai/patch-safety.md`](../../docs/ai/patch-safety.md).

- **`applyJSONToGraph` merge mode adds wires you didn't ask for** — with `clearExisting=false` it auto-connects new nodes to Audio Output / a MIDI source (an affordance for AI patches); any caller reproducing an *exact* sub-graph (snippet insert, copy/paste, duplicate) must pass `autoConnectNewNodes=false`. → [`docs/layout/snippets-clipboard.md`](../../docs/layout/snippets-clipboard.md)
- **`applyJSONToGraph` rebuilds the audio graph once, on return** — every add/remove of a node or cable inside it (and in its helpers `removePatchNode`, `applyModulationEntries`) uses `UpdateKind::none`, and `RebuildOnExit` rebuilds the render sequence when it returns. A synchronous rebuild per op made a paste or a track duplicate cost (ops x graph size). New topology ops in that path must stay deferred. → [`docs/architecture/module-base.md`](../../docs/architecture/module-base.md#restoring-a-snapshot-is-a-diff-not-a-rebuild)
- **Patch format forward-compatibility: reserved fields stay reserved** — `"timeline"`, `"macros"` (P8-12 — macro card layout, app-authored project data), `"midiRemote"` (FRO124 — MIDI controller assignments, app-authored project data), `"mixerPanLaw"` (FRO325 — the mixer's per-project pan law, app-authored project data), `"mixerView"` (which mixer channels are pinned or hidden, app-authored project data) and `"view"` (the graph canvas zoom and pan, app-authored project data) all stay refused on the untrusted path; params stay a flat scalar map (time-varying data belongs under `"timeline"`); `schemaVersion` is never bumped for additive changes; per-node `uuid` is trusted-only; unknown top-level keys survive save/load inert. AI-authored timeline data enters through a **separate door**, `synth::validateTimeline` — extend that, never weaken the `"timeline"` refusal. The AI may create a bound track only through the `addInstrumentTrack` timeline op, binding only the `Track In` that op creates; `Track In` stays non-authorable in patches. → [`docs/ai/patch-format.md`](../../docs/ai/patch-format.md) · [`docs/layout/macro-cards.md`](../../docs/layout/macro-cards.md) · [`docs/control/midi-remote.md#persistence-and-the-trust-boundary`](../../docs/control/midi-remote.md#persistence-and-the-trust-boundary) · [`docs/ai/timeline-ops.md#addinstrumenttrack`](../../docs/ai/timeline-ops.md#addinstrumenttrack)
- **Conversation-history persistence is resolved server-side from the entitlement, never trusted from a client header** — the client only decides which UI to *show* (`isProPlan(AccountSnapshot)`); the server checks the signed-in account's plan on every request. Same class of boundary as `trusted=true`. → [`docs/ai/history.md`](../../docs/ai/history.md#server-side-conversation-history)
- **Persist a rotated refresh token before using the access token that came with it** — every `AccountService` sign-in/refresh returns a *new* refresh token, and the auth service revokes the whole family if a consumed one reappears. Save it to the `TokenStore` and confirm success **before** exposing the access token or notifying listeners (`AccountService::completeSignIn` is the one funnel). → [`docs/ai/accounts.md`](../../docs/ai/accounts.md#rotation-before-use)
- **AI model discovery ordering** — `AIChatComponent`'s ctor-time `refreshModels()` is a no-op with no provider installed; any owner that installs one afterward MUST call `refreshModels()` again post-`setProvider()`, or every `/api/chat` gets a 400. → [`docs/ai/chat-component.md`](../../docs/ai/chat-component.md#model-discovery-ordering-contract)
- **A modulation names its target by `destPort` or `destParam`, and every id in an edit plan is distinct** — at least one of the two (both present must agree; neither is `ModulationInvalidPort`), enforced in `validatePatch`; patch node ids, `instrumentId`s, `envelope.id`s and insert ids share one namespace, enforced by the plan validator (`AIIntegrationServiceProjectEditRun.cpp`). Never by the schema alone: `getPatchSchemaWithTimelineOps()` makes both fields optional because a grammar cannot say "one of". → [`docs/ai/patch-format.md`](../../docs/ai/patch-format.md#a-modulations-destination-destport-or-destparam) · [`docs/ai/timeline-ops.md#one-edit-plan`](../../docs/ai/timeline-ops.md#one-edit-plan)

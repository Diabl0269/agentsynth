# Timeline invariants (Source/Timeline/)

Engine-level timeline rules (`EpochExchange`, publish order, the `timelineChanged` seam, uuid mirroring) live in `Source/CLAUDE.md`, which also loads for work here.

- **Audio clips STREAM, and only the prefetch thread may touch a reader** — nothing on the audio path may open, read or map a file, and nothing pulls a clip into RAM whole (that is `SamplerModule`'s model, wrong here). Every `juce::AudioFormatReader` is owned exclusively by the prefetch thread; the message thread only publishes an assignment table. The ring's fill/publish order is load-bearing — read the doc before touching it. An offline bounce steers only `wantedFrame`, via `waitUntilPrimed` with nothing rendering, and counts a timeout as a reported dropout — never by reading a file from the render loop. → [`docs/architecture/app-wiring.md#audioclipstreamer-disk-streaming-clip-playback`](../../docs/architecture/app-wiring.md#audioclipstreamer-disk-streaming-clip-playback) · [`docs/modules/modules.md#track-audio-module-timeline-audio-source-hidden`](../../docs/modules/modules.md#track-audio-module-timeline-audio-source-hidden)
- **A hosted plugin's automation lanes never bind by index alone** — every lane-resolution call site shares ONE resolver, `synth::resolveLaneParameter` (`Source/Timeline/AutomationBinding.h`): exact id match wins; a stored `paramIndexHint` rescues only a parameter with no stable id at all; a hinted index that names a *different*, still-identified parameter **orphans** the lane rather than silently rebinding. → [`docs/modules/modulation.md#hosted-plugin-parameters-as-automation-lanes`](../../docs/modules/modulation.md#hosted-plugin-parameters-as-automation-lanes) · [`docs/modules/modules.md#load-ux`](../../docs/modules/modules.md#load-ux)
- **A lane lives on the track that plays its module** — `synth::resolveTrackOwners` (`TrackOwnership.h`) is the one ownership rule (exclusive: a node two tracks reach is unowned and its lane falls back to the shared Automation track); it mirrors auto-arrange's track claim, so change them together. → [`docs/timeline/automation.md#which-track-a-lane-lands-on`](../../docs/timeline/automation.md#which-track-a-lane-lands-on)
- **A modulator's amount lane is never empty, and is only removed with its routing** — an amount lane (`amount` on a routing's hidden Attenuverter, `Source/UI/Timeline/AutomationLanes/Modulators/ModulatorAmountLane.h`) is created by the first edit that also gives it points and removed when its last point goes (`writeAmountLane`), because the applier writes an empty lane's range default (0) every block while playing, silencing the modulator. It is identified by the Attenuverter's uuid from a live routing, never by the `amount` paramId alone. Projects with the retired LFO "sections" (`level` lanes) are migrated once on load (`MainComponent::migrateSectionsToAmountLanes`), never on a reconcile. → [`docs/timeline/automation.md#amount-lane`](../../docs/timeline/automation.md#amount-lane)

# Plugin-layer invariants (Source/Plugin/)

Host-mode rules (`HostMode::Hosted` never touches hardware; the stream-format hook) live in `Source/CLAUDE.md`, which also loads for work here.

- **A plugin editor must never call `Desktop::setDefaultLookAndFeel`** — it's process-global inside the host and would re-skin the host's own windows and every sibling plugin. Scope with `setLookAndFeel(&processor.getLookAndFeel())` on the editor itself; `ThemeManager`/`AppLookAndFeel` belong to the processor, since hosts recreate the editor repeatedly. → [`docs/architecture/plugin-layer.md#who-owns-what`](../../docs/architecture/plugin-layer.md#who-owns-what)
- **JUCE is patched, and the patch is load-bearing for the plugin window's right-click "Add to card"** -- `cmake/patches/juce-vst3-context-menu.patch` (applied by FetchContent's `PATCH_COMMAND`, a reused `FETCHCONTENT_SOURCE_DIR_JUCE` skips it) adds `juce::VST3PluginFormat::setHostContextMenuExtension`. Change the JUCE tag only together with a regenerated patch, and keep the deps cache keys hashing the patch files. VST3 only; AU gets nothing. -> [`docs/development/juce-patches.md`](../../docs/development/juce-patches.md), [`docs/control/plugin-card-layout.md#add-to-card-from-the-plugin-window`](../../docs/control/plugin-card-layout.md#add-to-card-from-the-plugin-window)
- **Same rule for a DETACHED Timeline/Mixer window** — `DetachedPanelWindow` (FRO12, P9-6) is a second top-level window a plugin editor can open; it scopes its own `setLookAndFeel()` the identical way, never touching the process-global default. → [`docs/mixer/panel.md`](../../docs/mixer/panel.md)

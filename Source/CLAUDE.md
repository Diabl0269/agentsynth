# Engine & threading invariants (Source/)

Loaded for any work under `Source/`. Supplements the root `CLAUDE.md` (which holds the always-loaded area map); the full mechanism and history live in the linked docs. Area-specific rules live in `Source/Modules/`, `Source/Timeline/`, `Source/AI/`, `Source/UI/`, `Source/Plugin/` `CLAUDE.md` files.

- **`AudioEngine::HostMode::Hosted` never touches hardware** — no audio device, no MIDI input (the host owns both; opening MIDI directly double-triggers notes). Drive it only through `prepareForHost`/`processHostBlock`/`releaseFromHost`. → [`docs/architecture/plugin-layer.md#host-modes-audioenginehostmode`](../docs/architecture/plugin-layer.md#host-modes-audioenginehostmode)
- **The device callback's render buffer is not the device's output pointers** — one buffer of `max(numIn, numOut)` channels serves both the Audio Input and Audio Output nodes (the graph renders in place), so device input is copied in before the graph runs and uncovered channels come from a scratch buffer sized in `audioDeviceAboutToStart` — the callback must never allocate. Audio input stays **opt-in**: absent saved state means `initialiseWithDefaultDevices(0, 2)`, and the restore path requests **0** input channels so a saved setup never switches a microphone on uninvited. Core never touches `ApplicationProperties`; state flows out via `onDeviceStateChanged`. → [`docs/architecture/audio-engine.md#audioengine`](../docs/architecture/audio-engine.md#audioengine)
- **A device/sample-rate change goes through ONE hook, and a take never spans it** — `AudioEngine::handleStreamFormatChange` (called from both `audioDeviceAboutToStart` and `prepareForHost`) is where every prepare-path consumer is added, in order, transport first — never duplicated per call site. It invalidates all clip streams (a rate change is a discontinuity the ring's self-healing miss can't detect). An in-flight take is finalized at the boundary, never continued: `MainComponent::AudioTake` freezes `captureSampleRate`/`captureBpm`/`captureRecordingLatencySamples` at record-on; reading them live at commit mixes two real rates under one declared one. → [`docs/architecture/app-wiring.md#device--sample-rate-changes`](../docs/architecture/app-wiring.md#device--sample-rate-changes)
- **Timeline data crosses threads only via an `EpochExchange`** — `AudioEngine::renderPass` is the one site that opens the snapshot and binding exchanges, exactly once each per render pass; never cache a returned reference across passes (epoch reclamation makes it a use-after-free). Modules read via `getPlayHead()` downcast to `synth::TransportService*` (same block-only lifetime; can be null). `AudioEngine::publishTimeline` is the only publisher — **snapshot first, bindings second** — and must be re-called after any graph change. Every `TimelineDoc` edit goes through its mutation API, never a direct field write. → [`docs/architecture/timeline.md#timelinesnapshot-the-audio-threads-view-of-the-timeline`](../docs/architecture/timeline.md#timelinesnapshot-the-audio-threads-view-of-the-timeline)
- **MIDI Remote never takes a lock, allocates, or logs on the MIDI path** — `RemoteEngine::handleMessage` runs on a MIDI driver thread (standalone: one per open `juce::MidiInput`, several concurrently) or on the *audio* thread (`HostMode::Hosted`, per message out of `processHostBlock`). The live mapping table is an immutable `RemoteMappingSnapshot` published by atomic pointer swap and reclaimed by a reader count, NOT by `EpochExchange` (single-consumer: one epoch per audio block, and the MIDI path has no block) and NOT by `std::atomic<std::shared_ptr<>>` (a spinlock or mutex pool in every shipping standard library). The only thing that thread writes is its own source's lane — its `juce::AbstractFifo` rings plus the lane's fixed-size paired-CC / NRPN half cache (`RemoteLaneState.h`, plain memory, producer-thread-only, never read by the drain; FRO140) — one lane per source, index assigned on the message thread and never recycled, because `AbstractFifo` is single-producer and two devices really can move at once. The drain is a plain 60 Hz `juce::Timer` gated on "table non-empty or learn armed"; an `AsyncUpdater` kick is forbidden (`triggerAsyncUpdate` takes a `CriticalSection` and allocates). Applying happens on the message thread through the mouse's own path — `beginChangeGesture` / `setValueNotifyingHost` / `endChangeGesture` — so `AutomationRecorder`, `AppUndoManager` and every host see a real gesture. Controller feedback (FRO139) is sent from this same message-thread drain, never from the MIDI path — the MIDI/audio thread never touches a `RemoteFeedbackSink`. → [`docs/control/midi-remote.md#how-does-a-hardware-value-reach-a-parameter`](../docs/control/midi-remote.md#how-does-a-hardware-value-reach-a-parameter) · [`docs/control/midi-remote.md#threading-the-mapping-table-crosses-threads`](../docs/control/midi-remote.md#threading-the-mapping-table-crosses-threads) · [`docs/control/midi-remote.md#controller-feedback`](../docs/control/midi-remote.md#controller-feedback) · [`docs/control/midi-remote.md#14-bit-and-nrpn-encodings`](../docs/control/midi-remote.md#14-bit-and-nrpn-encodings)
- **`MainComponent` owns the app's live `TimelineDoc`, and every graph change has to tell it** — publish-to-the-audio-thread happens at ONE seam (`MainComponent::timelineChanged`, which also rebinds the `AutomationRecorder`); any path that adds/removes/replaces nodes must run the reconcile pass afterwards, and a new "replace the graph" path means a new entry in the hook inventory table in [`docs/architecture/app-wiring.md`](../docs/architecture/app-wiring.md#app-wiring--who-owns-the-timeline-and-every-hook-that-keeps-it-in-step). An orphaned track binding is never re-established automatically — the user picks a node from the chip menu. → [`docs/timeline/tracks.md`](../docs/timeline/tracks.md#a-binding-is-never-re-established-automatically)
- **Anything that replaces the open document asks first, and asks through the ONE gate** — `MainComponent::guardUnsavedChanges(actionLabel, proceed)` fronts New Patch, Open, the Load menu's factory-preset branch and app quit. It is **asynchronous**: hand it the destructive work as `proceed` and return, never do the work and prompt afterwards, and never assume `proceed` runs (Cancel, a failed save and a cancelled save dialog all abandon it). Dirty state has exactly one funnel, the `AppUndoManager` change broadcast — not `timelineChanged`, which also fires for the reconcile pass and would mark a freshly loaded project dirty. That broadcast is **async and therefore always potentially stale**, so the listener RECOMPUTES `isDirty_` from `AppUndoManager::getEditSerial()` against the baseline `MainComponent::markDocumentClean()` captured; never write `isDirty_ = false` directly, or a notification already queued (New Patch queues two) will re-dirty the document you just reset. Any path that replaces the document with something that is not a bundle must also clear `currentBundleDir_` + `refreshAssetRoots()`, or the next silent Cmd+S overwrites a project the user is no longer looking at. Autosave is deliberately **outside** this gate — it never replaces the open document, only writes a side file. → [`docs/architecture/project-bundle.md#dirty-state-and-the-unsaved-changes-guard`](../docs/architecture/project-bundle.md#dirty-state-and-the-unsaved-changes-guard)
- **Autosave writes a sidecar (`autosave.json`), never `project.json`, and rotates a configurable number of numbered backups** — `MainComponent::maybeAutosave()` gates on the undo edit serial having moved since the last autosave (not `isDirty_`, which autosave never clears) and never fires during a recording take (`isRecordingActive()`) or a bounce (`isBounceInProgress_`); `ProjectBundle::discardAutosave` never touches the backup history, only the live sidecar. A bounce renders in chunks via `synth::BounceRunner` ticking a `juce::Timer` between them, NOT by blocking the message thread for the whole take — `timerCallback()` runs mid-render, which is exactly why the flag exists (there is no "the message thread is blocked" freebie left to lean on). `guardUnsavedChanges` (see above) checks the same flag, for the same reason: New Patch/Open/Load preset/Quit must not mutate or replace the graph out from under a live render. → [`docs/architecture/project-bundle.md#autosave-and-crash-recovery`](../docs/architecture/project-bundle.md#autosave-and-crash-recovery)
- **Mixer solo is a render-time PER-LEG gate owned by the engine, never a parameter write** — each `ChannelStripModule` keeps its own solo flag (trusted extra state, not an `AudioParameter`); `AudioEngine` owns the soloed-strip count and publishes "any soloed?" per render pass via `TransportService::setMixerSoloActiveForBlock`. The count is **recounted by scanning the graph**, inside `publishTimeline` — which is why a deleted or undone soloed strip can't leave the mix stuck silent. Any path that replaces the graph without reaching `publishTimeline` (today: the plugin's `setStateInformation`) must call `refreshSoloGate()` itself; a UI toggles solo only through `AudioEngine::setChannelStripSoloed`. Never implement solo by fanning `setMuted()` across strips — that clobbers the user's own mutes and is host-visible. WHAT gets silenced is decided per LEG, not per strip (FRO15): `refreshSoloGate` also runs `synth::computeSoloAudibleLegs` and hands each strip its own audible-leg mask, published OPEN BEFORE CLOSE (pass 1 ORs, pass 2 assigns) so a render pass between the two passes is never wrongly silent. The mask defaults to 0 on purpose — an unpublished strip behaves exactly as the pre-send whole-buffer clear did, so a missed publication can never leak into a soloed mix. → [`docs/mixer/mixer.md#solo-is-a-render-time-gate`](../docs/mixer/mixer.md#solo-is-a-render-time-gate) · [`docs/mixer/sends-and-buses.md`](../docs/mixer/sends-and-buses.md) · [`docs/architecture/audio-engine.md#mixer-solo-gate`](../docs/architecture/audio-engine.md#mixer-solo-gate)
- **A node's uuid must be mirrored into its processor at every write site** — `node->properties` is message-thread-only, so every `properties.set("uuid", ...)` pairs with `ModuleBase::setNodeUuid` (`mirrorUuidIntoProcessor` in `AIStateMapper/AIStateMapperInternal.h`; `MainComponent`'s add-track flow). The lock-free `getNodeUuid()` is only sound because the uuid is written once, before the node is audio-visible — never rewrite or clear it. → [`docs/architecture/module-base.md#node-uuid-mirror-setnodeuuid--getnodeuuid`](../docs/architecture/module-base.md#node-uuid-mirror-setnodeuuid--getnodeuuid)
- **A bounce suspends external MIDI delivery, not just the audio device** — `AudioEngine::suspendDeviceCallback()` detaches the audio callback only; a real MIDI driver thread keeps calling `handleIncomingMidiMessage` throughout a render regardless, which is the one path that bypasses the empty-`MidiBuffer` guarantee every other offline block gets. `BounceSession` also holds `suspendExternalMidi()`/`resumeExternalMidi()` (an atomic flag `handleIncomingMidiMessage` checks itself, not a `juce::MidiInput::stop()`/`start()`, which only narrows the race) for the render's duration — any new bypass of `BounceSession`/`BounceExporter::bounce()` that drives an offline render must pair the two the same way. → [`docs/architecture/audio-engine.md#audioengine`](../docs/architecture/audio-engine.md#audioengine)
- **No non-ASCII bytes in a string literal** — `juce::String`'s `const char*` constructor decodes bytes as Latin-1, not UTF-8, so `"Rename…"` ships as mojibake; a hex escape (`"\xe2\x80\xa6"`) is the same bytes and fails identically. Use plain ASCII, or say the encoding out loud with `juce::CharPointer_UTF8` / `juce::String::fromUTF8`. Guarded by `scripts/tests/check-nonascii-literals.test.sh` (Lint job); comments are exempt. → [`docs/development/ascii-literal-guard.md`](../docs/development/ascii-literal-guard.md)
- **A non-finite sample (NaN/Inf) must never reach the device or the host** — `AudioEngine::renderNextBlock` scrubs one to `0.0f` in place as its very last step (FRO161), scoped to `mainProcessorGraph.getTotalNumOutputChannels()`. This is deliberately NOT in `MasterModule`: Master is spliced in only once a channel exists (absent from the default patch entirely) and is not last on the signal path even when present (Rec Tap, and the metronome's post-graph click, both sit after it) — `renderNextBlock` is the one place both host modes actually funnel through. A branchless IEEE-754 bit test, not `std::isfinite` (fast-math-proof, though this repo does not build with it today); `-0.0` and every denormal are finite and pass through untouched. → [`docs/architecture/audio-engine.md#audioengine`](../docs/architecture/audio-engine.md#audioengine)
- **No file over 1,000 lines, no function over 200** — a class that outgrows one file is split by concern into its own directory (root `CLAUDE.md` § Code structure), never grown further; a function that outgrows 200 lines is split into a named step or a real collaborator class. Enforced by `scripts/check-file-sizes.sh` and `scripts/check-function-sizes.sh`'s ratchet baselines. → [`docs/development/file-size-guard.md`](../docs/development/file-size-guard.md) · [`docs/development/function-size-guard.md`](../docs/development/function-size-guard.md)
- **`AudioEngine::shutdown()` always fires `onBeforeShutdown` before freeing graph state** — as its very first statement, before `mainProcessorGraph.clear()` frees any node's `AudioProcessorParameters`. Any UI owner holding live parameter attachments into the graph (e.g. `GraphEditor`'s `ModuleComponents`) must wire this hook to detach them, or a caller that invokes `shutdown()` directly — not only through that owner's own destructor — hits a heap-use-after-free (FRO87). `MainComponent` wires/clears it unconditionally in both Standalone and Hosted mode; see `AudioEngine.h`'s doc comment on the member itself.

# UI & theming invariants (Source/UI/)

Mechanism and history live in the linked docs.

- **No unconditional per-tick repaint** — `ModuleComponent` is buffered-to-image with a gated 15 Hz timer; the 30 Hz GraphEditor animation composites cached images; a theme switch is exactly one re-skin pass. All animations use `AnimationDriver` (VBlank-driven, time-bounded). Exactly two exceptions: the AI thinking spinner (in-flight only, region-confined) and the timeline playhead (strip-confined, playing-only). → [`docs/layout_visuals_animation.md §2–3`](../../docs/layout_visuals_animation.md)
- **A cable is not a graph edge** — one drawn wire can be 1 edge, 2 edges + a hidden attenuverter node, or N poly-bus edges. Never identify, hit-test, colour or delete a cable by `AudioProcessorGraph::Connection`; go through `GraphEditor::buildVisibleCables()`, the single enumeration feeding both `paint()` and hit-testing. Wire colour resolves only via `synth::ui::resolveCableColour` — reading a `*Wire` theme token at a paint site breaks user colour overrides. → [`docs/layout_selection_canvas.md §3`](../../docs/layout_selection_canvas.md) · [`docs/theming.md §11`](../../docs/theming.md)
- **Themes don't swap fonts** — all built-ins share Inter + JetBrains Mono; swapping the embedded typeface *family* at runtime corrupts text (JUCE 8 + CoreText). Themes differ by colour/treatment/glow only. → [`docs/theming.md`](../../docs/theming.md)
- **No high-frequency logging** — a global `juce::Logger` (Debug builds) pipes `writeToLog` into a UI-thread console; never add per-sample / per-frame / per-parameter / per-connection logs (one caused a multi-second freeze; guarded by `AIStateMapperTest.PresetLoadDoesNotSpamLogger`). → [`docs/AI_Engine_chat_component.md`](../../docs/AI_Engine_chat_component.md)
- **A module/macro rebuild mid-gesture cancels any live drag, never leaves it waiting on a `mouseUp` that can't arrive** — `ModuleComponent`/`MacroCardComponent::mouseDown` arm the drag-preview state (`GraphDragDropController::dragPreviewActive_` since FRO77 PR3, forwarded via `GraphEditor::isDragPreviewActive()`) / `GraphEditor`'s `selectionDragActive` and reset them only from their own `mouseUp`; `detachAllModuleComponents()`/`updateComponents()`/`syncMacroCards()` destroying that component first (an async apply, or the dragged node/macro itself vanishing) leaves no component left to deliver one. Call `GraphEditor::cancelLiveDragGestures()` from every such removal site. → [`docs/layout_selection_canvas.md §1.4`](../../docs/layout_selection_canvas.md)
- **Three collaborators own most of `GraphEditor`'s state, each reached only through `GraphCanvasHost`** — `SmartConnectionEngine` (FRO77 PR1, smart-connection suggestions), `MacroGroupController` (FRO77 PR2, macro grouping/geometry/ports/bypass-mute), `GraphDragDropController` (FRO77 PR3, drag-preview + alignment guides + drag-and-drop targets). `GraphEditor` holds one instance of each and forwards its own unchanged public API. → [`docs/architecture.md` §7](../../docs/architecture.md)
- **A track header never sees the graph — its channel comes through one seam** — `TimelineTrackHeaderComponent` stays graph-free and headless-testable against a stub host; everything it knows about the mixer CHANNEL its track plays into (the channel chip's name/meter, a linked track's rename/colour fan-out, and the M/S that drive the strip instead of note gating) arrives through `synth::ui::TrackChannelLinkSurface`, handed back by the single non-pure `TrackHeaderHost::getChannelLinkSurface()`. Every "not linked" answer is false/null and the header falls through to its existing behaviour unchanged, so the link can never half-apply. The real implementer is `TrackChannelLinkController`, owned by `MainComponent`. → [`docs/mixer.md §5.2`](../../docs/mixer.md) · [`docs/timeline_panel_tracks.md §3`](../../docs/timeline_panel_tracks.md)
- **A menu whose options a background thread can mutate resolves clicks against a build-time snapshot, never a re-run collector** — the Instrument -> Plugin picker's known-plugin list is mutated by `PluginScanService::runScan` off the message thread, so `TimelinePanelComponent::applyAddTrackMenuChoice` indexes `instrumentPluginMenuSnapshot_` (captured in `buildAddTrackMenu()`), not a fresh `collectInstrumentPluginMenuOptions()` call — a scan finishing mid-menu can otherwise resolve a click against a plugin the menu never showed there. → [`docs/timeline_panel_tracks.md §3`](../../docs/timeline_panel_tracks.md)
- **Any mixer UI object holding a parameter or module pointer unbinds through `MixerPanelComponent::unbindAllColumns()`** — the fader, the pan attachment, the EQ thumbnail and (FRO15) every `MixerSendList` row's `sendNLevel` attachment are live pointers into graph nodes, and `GraphEditor::onBeforeDetachAllModuleComponents` is the one seam every graph-replacing path (undo/redo restore, New Patch, Load, AI patch apply) AND every single-node removal command — `GraphEditor::deleteSelection()` (a canvas "Delete", `deleteMacroAndMembers`), `requestDeleteModule()` (a card's own delete button / "Delete Module") and `replaceModule()` ("Replace with...", FRO103) — reach BEFORE they free them — the latter has no rebuild of its own to lean on (`reconcileTimelineBindingsOnly()`, its only guaranteed post-apply hook, deliberately never rebuilds the mixer), so a stale binding could sit until an unrelated later graph edit finally destroys and dereferences it. A new bound control in a column means a new line in `MixerColumnComponent::unbindFromGraph()`, not a hope that rebuild order saves it. → [`docs/mixer.md §5.15`](../../docs/mixer.md)
- **A single `graph.removeNode()` frees its processor synchronously, same as a full graph-replacing restore** — a live single-node removal outside `onBeforeDetachAllModuleComponents`'s reach (today: `MixerInsertList::removeRow()`'s own row "Remove") has no equivalent built-in hook, so a UI object holding a raw pointer into that ONE node must either get a caller-side pre-removal unbind (`MixerInsertList::onBeforeNodeRemoved`, fired from `removeRow()` before `removeNode()`) or check the node's own liveness before dereferencing (`MixerEqThumbnail::detachListeners()`'s optional graph/NodeID) — a defensive check beats chasing every present and future single-node removal call site with its own hook. → [`docs/mixer_implementation.md` P9-10](../../docs/mixer_implementation.md)
- **No file over 1,000 lines** — `GraphEditor.cpp` is this directory's cautionary tale (9,000+ lines before the guard); a class that outgrows one file is split by concern into its own directory (root `CLAUDE.md` § Code structure). `Source/UI/` holds only area directories — `Graph/` (GraphEditor, ModuleComponent, cables, selection, minimap, mod matrix), `Timeline/` (panel, clip lanes, ruler, headers, transport, automation lanes, edit tools), `PianoRoll/`, `Library/` (module library), `Macros/`, `ModuleViews/` (per-module visualizers), `Settings/`, `Assistant/` (AI chat + account), `Chrome/` (toolbar, status bar, welcome, export, shared popups), `Layout/` (layout/focus/animation primitives), `Theme/`; a new file goes into its area, never back into this directory. → [`docs/testing.md`](../../docs/testing.md)

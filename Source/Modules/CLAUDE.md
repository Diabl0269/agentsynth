# Module & channel invariants (Source/Modules/)

The bypass/mute two-branch contract is stated in full in the root `CLAUDE.md` — it applies to every `processBlock` here. Mechanism and history live in the linked docs.

- **A second audio leg goes on a new `kRightBase` block, never on ch1** — on the voice modules ch1 is already a CV input, so relabelling it "Right" repoints every saved patch that modulates it. Wavetable/Oscillator/Filter/VCA put `Audio R` on a dedicated block above the mod-CV inputs: keep the declared output count above every CV input index, bound end-of-block CV clears at `kRightBase` (not `getNumChannels()`), and use `ModuleBase::panGains` (balance law, unity centre — equal-power would quieten every mono patch by 3 dB). Dual I/O "off" on these modules exposes the **left leg only** and must DROP cables on the hidden right block. Pair legs via `ModuleBase::rightAudioLegChannel()`, never by assuming ch1. And when a module's visible jack count grows, override the default port map — the fallback marks unclaimed channels as phantom poly heads and `getJackTargets` duplicates wires. The Dual I/O toggle itself is **inherited, never registered**: `ModuleBase`'s constructor grants it from the channel shape (`hasStereoOutputPairShape`: ≥2 in, exactly 2 out) along with the collapsing output jack, so a new stereo module needs no Dual I/O code — never re-introduce a per-module opt-in call. Modules whose shape collides but aren't a real stereo pair (Comparator, Rec Tap) opt out explicitly via `StereoAudio::None` with a reason recorded in the `StereoDeclaration` sweep. → [`docs/modules/fx-modules.md#the-toggle-is-inherited-not-registered`](../../docs/modules/fx-modules.md#the-toggle-is-inherited-not-registered)
- **A detector key input uses `PortRole::Sidechain` and is never a signal edge** — Compressor/Gate Key L/R are APPENDED above every existing input (ch7/ch8 via `ModuleBase::mapStereoKeyInput`, never renumbering saved channels), and `isSignalPathInputRole` keeps them out of the mixer's walks, or a bass keyed from a kick reads as a bus. The detector keys only while `ModuleBase::isSidechainConnected()` — published from the message thread by `synth::publishSidechainConnections` on every graph change, never inferred from the key's level. → [`docs/modules/fx-modules.md#key-inputs-sidechain`](../../docs/modules/fx-modules.md#key-inputs-sidechain)
- **A module's channel count is fixed for its lifetime** — JUCE settles the bus layout in the `ModuleBase` constructor; renegotiating drops every existing connection. Variable-port modules (Macro bank, Audio Input, Hosted Plugin) declare their **maximum** and vary only `getVisibleInput/OutputPortCount()`, clearing hidden channels each block; when the visible count shrinks, drop routings on the now-hidden jacks (`GraphEditor::dropRoutingsOnHiddenJacks`). A hosted plugin wider than `kMaxPluginChannels` is **refused with a message, never truncated**. → [`docs/modules/modules.md#hosted-plugin-module-third-party-vst3--au-hidden`](../../docs/modules/modules.md#hosted-plugin-module-third-party-vst3--au-hidden)
- **A Channel Strip's input shape is written once and never changes; the solo gate applies in BOTH of its branches, per LEG** — Mono/Stereo is locked by `setShape()` / trusted extra state / the first `prepareToPlay`, and a later width change is refused (changing width = replacing the strip). Its right leg is on `kRightBase` = 4 with ch1–3 reserved and cleared. The mixer solo gate (`TransportService::isMixerSoloActiveForBlock`) silences a non-soloed strip in the dry bypass branch as well as the normal one, and Master's Direct input likewise — that is layering an engine decision on the output, not the forbidden `isBypassed() || isMuted()` collapse (the two branches stay separate). A strip's SENDS (FRO15) are four fixed output legs on raw channels 8–15, declared at the maximum and varied only by the visible jack count — every `processBlock` branch must clear every reserved and inactive send channel, or a stale block from the previous callback leaks into a bus; mute clears them all, and the per-leg solo mask decides which survive. → [`docs/modules/modules.md#channel-strip-module-mixer-channel-hidden`](../../docs/modules/modules.md#channel-strip-module-mixer-channel-hidden) · [`docs/mixer/sends-and-buses.md`](../../docs/mixer/sends-and-buses.md)
- **A meter reader takes its own `PeakMeterLatch` slot and never reads another reader's** — `ChannelStripModule`/`MasterModule::takeMeterPeak(MeterReader, leg)` is consume-on-read (read-and-reset), so the mixer column (`MeterReader::Mixer`) and a track header's channel chip (`MeterReader::TrackHeader`) poll independently; a new consumer gets a new enumerator in `Source/Mixer/PeakMeterLatch.h`, never an existing one repurposed. `AudioEngine::takeOutputMeterPeak` (FRO148, the Master column's post-insert reading) is a `MeterReader::Mixer` consumer of the same kind, latched after the whole graph. → [`docs/mixer/panel.md#what-the-mixer-shows`](../../docs/mixer/panel.md#what-the-mixer-shows)
- **Every Wavetable warp mode must prove it doesn't alias** — warps run *after* mip selection, so a new mode needs one of the two documented defences (a `warpRateFactor` entry or the `warpNeedsOversampling` flag) **and** an entry in the parameterised `WavetableWarpAliasTest` / `WavetableWarpBoundsTest` suites, which iterate `Warp::Count` so an unhandled mode fails the test run instead of shipping. → [`docs/modules/wavetable.md#warp`](../../docs/modules/wavetable.md#warp)
- **A parameter that isn't a gain control must not add gain.** Drive/character-style knobs normalise their output (Ring Modulator divides its wet signal by Drive): an unnormalised drive once added +18 dB and the device's hard clip erased the rest of the mix. `ModuleGainAudit` (`Tests/Engine/GainStaging/ModuleGainAuditTests.cpp`) sweeps every parameter of every audio module and fails above +6 dB unless the parameter is on its allow-list with a reason; a new module goes into its spec list, and a new allow-list entry needs a real justification, not a bumped ceiling. → [`docs/development/gain-staging.md`](../../docs/development/gain-staging.md) · [`docs/modules/fx-modules.md#ring-modulator-module`](../../docs/modules/fx-modules.md#ring-modulator-module)
- **A message-thread-rendered lookup table crosses to the audio thread as a fixed-size array under a SpinLock try-lock with a pending flag** (`LFOModule::publishCustomTable`/`adoptPendingCustomTable`, after Wavetable's `publishLoadedTable`); the audio copy is private, sized at compile time, and valid from construction. → [`docs/modules/lfo.md`](../../docs/modules/lfo.md)
- **Normalling is render-time, never an edge** (FRO324) — a Dual I/O module's Right borrows Left, sample-exact, while Right is unpatched: `AudioEngine::refreshNormalling` (message thread, beside the mixer solo recount, AND from `changeListenerCallback` on the graph's own change broadcast — a plain canvas cable edit reaches neither `publishTimeline()` nor `setStateInformation`) sets `ModuleBase`'s `normalLeftToRight_` atomic, and `ModuleBase::applyLeftRightNormalling()` copies raw ch0 onto `rightAudioLegChannel()` at the very top of `processBlock`, before the bypass/mute branches, so both see a filled Right leg exactly as if the user had cabled it. Only a module with a genuine stereo AUDIO input pair opts in — `hasStereoAudioInputPair()` overridden `true` in the FX that read their input through `mapStereoPairInput`/`mapStereoKeyInput` and in the split-block `Filter`/`VCA` — never inferred from channel shape (Voice Mixer's ch0-7 are eight independent voice inputs, not a stereo pair, despite sharing the same `dualIO` toggle for its own OUTPUT jack). A collapsed (non-Dual) jack already fans one cable onto both raw legs, so it never normals. Audio Output gets the same policy directly in `AudioEngine::renderNextBlock` (its ch0→ch1 copy, right after the render pass). → [`docs/architecture/audio-engine.md#normalling-fro324`](../../docs/architecture/audio-engine.md#normalling-fro324) · [`docs/modules/fx-modules.md#right-borrows-left-while-unpatched-fro324`](../../docs/modules/fx-modules.md#right-borrows-left-while-unpatched-fro324)
- **`ModuleBase::processBlock` is `final`; override `processModuleBlock`** (FRO326) — the base averages any raw input fed only by whole stereo pairs (`applyInputDownMix`, mask from `synth::publishStereoDownMix` at the end of `AudioEngine::refreshNormalling`) before calling it, so a stereo pair into a mono jack plays 0.5·(L+R), never the graph's +6 dB unity sum. It runs before the bypass/mute branches and before `applyLeftRightNormalling`. A channel with any unpaired feed stays at unity. → [`docs/architecture/audio-engine.md#stereo-down-mix-fro326`](../../docs/architecture/audio-engine.md#stereo-down-mix-fro326)
- **A module that stores a file path in its extra state registers the key in `synth::ModuleFileRefs`** (`Source/Project/ModuleFileRefs.cpp`, key names in `ModuleFileStateKeys.h`) — keep the path absolute in memory; the registry is what makes a saved project write it bundle-relative, resolve it safely on load, and what Collect & Archive copies. An unregistered path key silently breaks when the project moves. → [`docs/architecture/project-bundle.md#projectbundle-agsproj`](../../docs/architecture/project-bundle.md#projectbundle-agsproj) · [`docs/architecture/app-wiring.md#collect--archive`](../../docs/architecture/app-wiring.md#collect--archive)
- **A module's per-sample loop does only per-sample work** — a scope feed goes through `VisualBuffer::pushBlock` / `pushConstant` (never `pushSample` in a loop: an atomic store pair per sample per module), nothing is allocated per block, and anything constant for the block (a unison detune ratio, an unchanged ladder coefficient — `LadderCoefficientSetter`) is computed once. Such per-node, per-sample costs are what cap how many modules a project holds before the audio crackles; measure with the render bench first. → [`docs/architecture/audio-engine.md#measuring-render-cost`](../../docs/architecture/audio-engine.md#measuring-render-cost)

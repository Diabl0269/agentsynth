# CLAUDE.md

Guidance for Claude Code (claude.ai/code) in this repository. Keep this file **lean** — it is the orientation layer (commands, conventions, critical traps). Detailed reference lives in `docs/` (map below); when you change behavior, update the relevant doc, not this file — docs must never go stale, so treat updating them as part of the change itself, not a follow-up.

## Project

Modular synthesizer (JUCE, C++20) with a node-based graph editor for sound design — connect audio/CV modules in a visual patching environment. Four CMake targets:

- **Core** — the library: all audio-processing modules + core logic. Headless-testable (no audio device, no GUI).
- **AppUI** — the editor UI (MainComponent, GraphEditor, ModuleComponent, chrome), shared by the app and the plugin.
- **AgentSynth** — the JUCE GUI application (`Main.cpp` on top of AppUI).
- **AgentSynthPlugin** — VST3 (+ AU on macOS) plugin wrapping the same AppUI/Core in a `juce::AudioProcessor`.

## Commands

```bash
# Build (ENABLE_PLUGIN defaults ON, so this also builds the VST3/AU plugin — pass -DENABLE_PLUGIN=OFF for an app-only loop)
cmake -S . -B build && cmake --build build

# Test  (ENABLE_TESTS defaults OFF — must opt in)
cmake -S . -B build -DENABLE_TESTS=ON
cmake --build build --target Tests
./build/Tests/Tests
./build/Tests/Tests --gtest_filter="E2EWorkflow*"   # E2E only

# Coverage  (threshold 85%)
bash scripts/coverage.sh

# CI script tests (both run in the Lint job; no compiler, no network, ~1s each)
bash scripts/tests/ci-cache-check.test.sh          # cache health check (also runs after every CI build)
bash scripts/tests/ci-install-linux-deps.test.sh   # Linux apt install + mirror failover

# Git hooks  (run once per clone — NOT auto-installed)
bash scripts/install-hooks.sh   # pre-commit: clang-format lint;  pre-push: lint + Release build + tests
# clang-format is pinned (.clang-format-version) — match CI locally:
pip install "clang-format==$(cat .clang-format-version)"
```

See [`docs/testing.md`](docs/testing.md) for the full build/test/CI/hooks reference.

## Critical invariants (break these and you ship bugs)

- **Bypass/mute contract** — in every signal-processing `processBlock`, use **two separate branches**: `isBypassed()` → dry pass-through (return early WITHOUT touching audio channels; clear only CV channels ≥2 so mod CV doesn't leak as audio); `isMuted()` → `buffer.clear()` then return. Never `if (isBypassed() || isMuted()) buffer.clear()` — that mutes on bypass instead of passing the signal through. **Exception:** modules with no dry audio path clear on bypass (still as two branches) — pure sources with no audio *input* (Oscillator, Poly MIDI) and audio-in/CV-out taps with no audio *output* (Envelope Follower, Comparator). → [`docs/architecture.md`](docs/architecture.md)
- **No high-frequency logging** — AIChatComponent registers a global `juce::Logger` (Debug builds only) that pipes `writeToLog` into a UI-thread console. Never add per-sample / per-frame / per-parameter / per-connection logs (one caused a multi-second freeze; guarded by `AIStateMapperTest.PresetLoadDoesNotSpamLogger`). → [`docs/AI_Engine.md`](docs/AI_Engine.md)
- **No unconditional per-tick repaint** — `ModuleComponent` is buffered to an image via `synth::ui::ZoomFrozenCachedImage` (never call `setBufferedToImage` on it — JUCE asserts and silently deletes the custom cache) with a gated 15 Hz timer; the 30 Hz GraphEditor animation composites cached images. A theme switch is exactly one re-skin pass. All UI animations use `AnimationDriver` (VBlank-driven, **time-bounded** — stops at `t=1`); never add free-running or continuous repaints. Exactly two exceptions: the AI thinking spinner (pulses only while a request is in flight, confined to its region) and the timeline playhead (strip-confined, playing-only, stops on stop/pause — its `requestRepaintStrip` seam is the repo's paint-count test pattern). → [`docs/layout_visuals_animation.md §2–3`](docs/layout_visuals_animation.md)
- **Themes don't swap fonts** — all built-ins share Inter + JetBrains Mono; swapping the embedded typeface *family* at runtime corrupts text (JUCE 8 + CoreText). Themes differ by colour/treatment/glow only. → [`docs/theming.md`](docs/theming.md)
- **Never relax `validatePatch` to raise the AI pass rate** — it is the security boundary for untrusted model output. Fix patch validity on the *generation* side, most upstream first: schema (`getPatchSchema` — the backend enforces it as a grammar) → bounded retry with the specific error → narrow repair → prompt. Measure with `Tools/AIPatchHarness` before changing anything; validation reports only the first error, so fixing one class unmasks the next. Related: a node's `"state"` object (`ModuleBase::setExtraState`, e.g. the Sampler's file path) is applied on the **trusted path only** — never honour it for provider output, or a patch suggestion becomes an arbitrary file read. → [`docs/AI_Engine.md`](docs/AI_Engine.md)
- **`applyJSONToGraph` merge mode adds wires you didn't ask for** — when `clearExisting=false`, it auto-connects new audio nodes to Audio Output and new MIDI-accepting nodes to an existing MIDI source. That's an affordance for AI-authored patches; any caller reproducing an *exact* sub-graph (snippet insert, copy/paste, duplicate) must pass `autoConnectNewNodes=false` or the inserted group gets spliced into the surrounding patch. → [`docs/layout_selection_canvas.md §1.5`](docs/layout_selection_canvas.md)
- **`trusted=true` on `applyJSONToGraph` is about parameter fidelity, not about skipping checks** — the untrusted apply path rescales any value inside `[0,1]` whose parameter range is wider (a heuristic for models that ignore ranges), which silently corrupts app-authored values like a 0.5 Hz LFO rate. Anything replaying our own `graphToJSON` output (presets, undo/redo, snippets) must apply trusted. When that data came off disk, run `validatePatch(..., trusted=false)` as a separate gate *first* so a hand-edited file is still rejected whole — `SnippetManager::insertSnippet` and `ProjectBundle::load` are the reference for this pairing. → [`docs/layout_selection_canvas.md §1.5`](docs/layout_selection_canvas.md)
- **Every Wavetable warp mode must prove it doesn't alias** — warps run *after* mip selection, so they can put back exactly the harmonics the pyramid exists to remove. A new mode needs one of the two documented defences (a `warpRateFactor` entry so `selectMip` sees its steepest slope, or a `warpNeedsOversampling` flag) **and** an entry in the parameterised `WavetableWarpAliasTest` / `WavetableWarpBoundsTest` suites — they iterate `Warp::Count`, so a mode added without a strategy fails the build's test run rather than shipping quietly. → [`docs/modules.md`](docs/modules.md)
- **AI model discovery ordering** — `AIChatComponent`'s ctor-time `refreshModels()` is a no-op if its `AIIntegrationService` has no provider yet; any owner (e.g. `MainComponent`) that installs a provider afterward MUST call `refreshModels()` again post-`setProvider()`, or `currentModel` stays empty and every `/api/chat` gets a 400. → [`docs/AI_Engine.md`](docs/AI_Engine.md)
- **`AudioEngine::HostMode::Hosted` never touches hardware** — it must not open an audio device or a MIDI input (the host owns both); drive it only through `prepareForHost`/`processHostBlock`/`releaseFromHost`. Opening a device fights the host for the hardware; opening MIDI input directly double-triggers notes the host already forwards through `processBlock`. → [`docs/architecture.md`](docs/architecture.md)
- **A plugin editor must never call `Desktop::setDefaultLookAndFeel`** — it's process-global inside the host and would re-skin the host's own windows and every sibling plugin. Scope with `setLookAndFeel(&processor.getLookAndFeel())` on the editor itself; `ThemeManager`/`AppLookAndFeel` are owned by the processor, not the editor, since hosts recreate the editor repeatedly. → [`docs/architecture.md`](docs/architecture.md)
- **CI cache is load-bearing and fails silently** — four rules: **`CMAKE_<LANG>_COMPILER_LAUNCHER` is per language** — setting only `C`/`CXX` left all 103 JUCE Objective-C++ units bypassing ccache and rebuilt cold every macOS run (~12 min of a 12 min 45 s job), invisible behind a plausible 54% hit rate because a compile that never reaches ccache counts as neither hit nor miss; any new language needs its own launcher (`scripts/ci-cache-check.sh` audits `build/build.ninja` and fails if a compile rule is missing one). Then: `ci.yml` keeps its `push: main` trigger (GitHub scopes caches per ref; without a main-scoped cache *no PR can restore one* and every build runs cold); `build/_deps` is keyed on `cmake/DependencyVersions.cmake` only, **never** on `CMakeLists.txt` (a module adding a source line must not invalidate a 350 MB entry — that overran GitHub's 10 GB repo cache limit and evicted everything); `CCACHE_DIR` is set explicitly per job (defaults differ by OS *and* ccache version — a mismatch means the cache is never saved). Add a dependency? Pin it in `cmake/DependencyVersions.cmake`. Guarded by `scripts/ci-cache-check.sh`. → [`docs/testing.md`](docs/testing.md)

- **A cable is not a graph edge** — one drawn wire can be 1 edge (audio/MIDI), 2 edges + a hidden node (attenuverter chain), or N parallel edges (poly bus). Never identify, hit-test, colour, or delete a cable by `AudioProcessorGraph::Connection`; go through `GraphEditor::buildVisibleCables()`, which is the **single** enumeration feeding both `paint()` and hit-testing (compute them separately and the drawn curve drifts from the clickable one). Wire colour resolves *only* via `synth::ui::resolveCableColour` — never read a `*Wire` theme token at a paint site, or user colour overrides silently stop applying. → [`docs/layout_selection_canvas.md §3`](docs/layout_selection_canvas.md) · [`docs/theming.md §11`](docs/theming.md)

- **A second audio leg goes on a new `kRightBase` block, never on ch1** — on the voice modules ch1 is already a CV input (Waveform / Position / Cutoff), so the FX Dual I/O trick of treating raw ch0/ch1 as the stereo pair is not available: relabelling ch1 "Right" repoints every saved patch that modulates that target. Wavetable, Oscillator, Filter and VCA all put `Audio R` on a dedicated block **above** the mod-CV inputs, which makes three things load-bearing: the module's declared **output** count must stay above every CV input index (that is what makes JUCE hand out private CV copies), every end-of-block CV clear must be **bounded at `kRightBase`** rather than running to `getNumChannels()` (or it erases the right leg), and placement uses `ModuleBase::panGains` — a balance law whose centre is unity, because an equal-power centre would quieten every existing mono patch by 3 dB. A processor (Filter, VCA) needs the block as an input too, with its own filter state per leg. All five split-block modules carry the same **Dual I/O** toggle as the FX, but it means something different on them: a collapsed jack can only fan to *adjacent* raw channels, so "off" exposes the **left leg only** rather than one jack owning both legs — and collapsing must therefore DROP the cables on the hidden right block. Anything pairing two modules' legs asks `ModuleBase::rightAudioLegChannel()`; assuming ch1 wires a voice module's CV as audio. One more trap once a module's **visible** jack count grows: `ModuleBase`'s default input map reports `isPolyGroupHead` for any raw channel below that count, so an unclaimed channel becomes a phantom second head on a real jack and `getJackTargets` hands out a duplicate wire — override the fallback instead of inheriting it. And the toggle itself is **inherited, never registered**: `ModuleBase`'s constructor grants it from the channel shape (`hasStereoOutputPairShape`: ≥ 2 in, exactly 2 out) along with the collapsing OUTPUT jack, so a new stereo FX needs no Dual I/O code — the five split-block modules pass `StereoAudio::Declared` and the two shape-collisions (Comparator, Rec Tap) pass `StereoAudio::None` with a reason recorded in the `StereoDeclaration` sweep. Never re-introduce a per-module opt-in call: the Ring Modulator shipped a stereo pair without one and no test could see it. → [`docs/modules.md`](docs/modules.md) · [`docs/fx_modules.md`](docs/fx_modules.md)

- **A module's channel count is fixed for its lifetime** — JUCE settles the bus layout in the `ModuleBase` constructor, and renegotiating it would drop every graph connection the node already has. A module whose port count varies (Macro bank; Audio Input, whose jacks follow the device; **Hosted Plugin**, whose jacks follow the loaded VST3/AU) declares its **maximum** channels up front and varies only `getVisibleInput/OutputPortCount()`, clearing the hidden channels each block. When the visible count shrinks, the owner must drop routings left on the hidden jacks (`GraphEditor::dropRoutingsOnHiddenJacks`) — an invisible jack cannot be unplugged. Hosted Plugin is the sharpest case and shows the second half of the rule: its 16/16 is fixed *before the plugin is even known* (the load is async, so the node is already wired by the time the channel count arrives), which is why an instance wider than `kMaxPluginChannels` must be **refused with a message, never truncated** — silently dropping a surround plugin's channels is a bug the user cannot see. → [`docs/modules.md`](docs/modules.md)

- **A hosted plugin's automation lanes never bind by index alone** — a hosted parameter is `juce::AudioProcessorParameter` (via `HostedAudioProcessorParameter`), not `RangedAudioParameter`, and its set can reshape between plugin versions. Every lane-resolution call site (the audio-thread binding build, `TimelineReconciler`, the AI-tool `writeLane` path, the automation recorder's rebind) shares ONE resolver, `synth::resolveLaneParameter` (`Source/Timeline/AutomationBinding.h`): exact id match wins; a stored `paramIndexHint` rescues ONLY a parameter with no stable id at all; a hinted index that instead names a *different*, still-identified parameter (a plugin update) **orphans** the lane rather than silently rebinding to it. → [`docs/modulation.md`](docs/modulation.md) · [`docs/modules.md`](docs/modules.md)

- **Persist a rotated refresh token before using the access token that came with it** — `AccountService`'s device-flow and refresh calls always return a *new* refresh token, and the auth service revokes the whole token family if a consumed one is ever presented again. Save the new refresh token to the `TokenStore` and confirm it succeeded **before** exposing the new access token or notifying listeners; a crash in that window otherwise leaves a dead token in the keychain and silently signs the user out next launch, with nothing to explain why. → [`docs/AI_Engine_providers_accounts.md §5`](docs/AI_Engine_providers_accounts.md)

- **Patch format forward-compatibility: reserved fields stay reserved** — `"timeline"` is refused on the untrusted path and must stay refused; opening it later requires a deliberate deletion of that check. Parameter values stay a flat scalar map forever; time-varying data belongs under `"timeline"`, never in a polymorphic param. `schemaVersion` defaults to 1 when absent and is never bumped for additive changes. Per-node `uuid` is honoured trusted-only and regenerated untrusted. Unknown top-level keys survive save/load via `PatchDocument` and are inert. AI-authored timeline data does exist but arrives through a **separate door**: `synth::validateTimeline` (`Source/Timeline/TimelineValidator.h`) gates the timeline tools' payloads, rejects unknown top-level keys instead of preserving them, and keeps assets, plugin blobs and lane record-arming trusted-only — extending this rule, never weakening the `"timeline"` refusal. → [`docs/AI_Engine.md`](docs/AI_Engine.md)

- **Conversation-history persistence is resolved server-side from the entitlement, never trusted from a client header** — a Pro-only feature gated by the server checking the signed-in account's plan on every request, the same class of invariant as `applyJSONToGraph`'s `trusted=true` boundary above: the mistake it prevents (a Free client simply sending the header/id anyway) is exactly as easy to introduce by accident later. The client only decides which UI/backend to *show* (`isProPlan(AccountSnapshot)` in `AIChatComponent`'s history panel and its `x-conversation-id` gating) — it must never be the thing that decides whether persistence actually happens. → [`docs/AI_Engine_providers_accounts.md §1`](docs/AI_Engine_providers_accounts.md)

- **The device callback's render buffer is not the device's output pointers** — with audio input live, ONE buffer of `max(numIn, numOut)` channels serves both the graph's Audio Input node (channels `[0, numIn)`) and its Audio Output node (channels `[0, numOut)`) — the SAME memory, since a `juce::AudioProcessor` renders in place. So the device's input is **copied into it before the graph runs** (the input block is const and the graph overwrites those channels), and any channel the outputs don't cover comes from a scratch buffer sized in `audioDeviceAboutToStart` — never in the callback, which must not allocate. Input is also **opt-in and stays that way**: `initialise()` restores a persisted `DEVICESETUP` when the owner supplied one via `setSavedDeviceState`, and otherwise takes the untouched `initialiseWithDefaultDevices(0, 2)` path, so *absent state is the legacy behaviour*; the restore path asks for **0** input channels needed, because that is the count JUCE falls back to when a saved setup doesn't pin its own and asking for 2 would switch a microphone on for a user who never did. Core never touches `ApplicationProperties` — the engine reports state through `onDeviceStateChanged` and the owner stores it. → [`docs/architecture.md`](docs/architecture.md)

- **Timeline data crosses threads only via an `EpochExchange`** — the audio thread reads the timeline through `TimelineSnapshotExchange::beginAudioBlock()` and the automation bindings through `EpochExchange<AutomationBindingTable>::beginAudioBlock()`, **exactly once each per graph render pass** (a pass is one callback normally, one 64-sample slice when `setAutomationSlicingEnabled` is on — `AudioEngine::renderPass` is the one site). Never cache a returned reference across passes: epoch reclamation frees a superseded value two blocks after retirement, so a cached pointer is a use-after-free. Modules don't call either: `renderPass` parks the snapshot on the transport, and a module downcasts `getPlayHead()` to `synth::TransportService*` to read it — same block-only lifetime, plus it can be null. `AudioEngine::publishTimeline` is the only publisher and must publish **snapshot first, bindings second** (a table's snapshot pointer is what keeps the two coherent), and must be re-called after any graph change or new nodes go unautomated. On the message side, every `TimelineDoc` edit goes through its mutation API — writing `tracks` directly silently breaks the revision counter, listeners, snapshot republication and (later) undo. → [`docs/architecture.md`](docs/architecture.md)

- **A node's uuid must be mirrored into its processor at every write site** — `node->properties.set("uuid", ...)` is message-thread-only data the audio thread can't read, so every writer pairs it with the mirror into `ModuleBase::setNodeUuid`: the three in `AIStateMapper.cpp` (via `mirrorUuidIntoProcessor`) plus `MainComponent::createTrackInNode` / `createTrackAudioNode` (the timeline's add-track flow). Add another without the mirror and a Track In / Track Audio node silently stops matching its timeline track. The lock-free `getNodeUuid()` read is only sound because the uuid transitions empty→value exactly once, before the node is audio-visible — never rewrite or clear it. → [`docs/architecture.md`](docs/architecture.md)

- **Audio clips STREAM, and only the prefetch thread may touch a reader** — `AudioClipStreamer` exists so a ten-minute take costs one ring (~1 MiB), never the file: nothing on the audio path may open, read or map a file, and nothing may pull a clip into RAM whole (that is `SamplerModule`'s model, and it is the wrong one here). Every `juce::AudioFormatReader` is owned **exclusively** by the prefetch thread — the message thread publishes an assignment table under a lock and never touches a reader, a ring or a window atomic, which is what makes "never free a reader the prefetch thread is using" true by construction rather than by a retire list. The ring's fill order is load-bearing: shrink `ringStartSourceFrame` **before** overwriting slots, publish `ringEndSourceFrame` **after** writing them, and collapse the window (end first) before a reposition. Reverse either and the audio thread reads a torn window. The one thing a non-audio thread may steer is `wantedFrame`, and only through `waitUntilPrimed` with nothing rendering: an offline bounce outruns the prefetch thread (and starts from an `invalidateAllStreams`), so it must block until each ring covers the frames it is about to read, count a timeout as a reported dropout, and never "fix" the problem by loading the clip or reading a file from the render loop. → [`docs/architecture.md`](docs/architecture.md) · [`docs/modules.md`](docs/modules.md)

- **`MainComponent` owns the app's live `TimelineDoc`, and every graph change has to tell it** — publish-to-the-audio-thread happens at ONE seam (`MainComponent::timelineChanged`, which also rebinds the `AutomationRecorder`), and any path that adds, removes or replaces graph nodes must run the reconcile pass afterwards or a track's binding chip lies about which node it plays through. A new "replace the graph" path means a new entry in the hook inventory table in [`docs/architecture.md` §8](docs/architecture.md) — that table is the definitive list, not a summary. A binding is **never** re-established automatically, least of all by name: an orphaned track stays orphaned until the user picks a node from the chip menu. → [`docs/timeline_panel_core.md §3`](docs/timeline_panel_core.md)

- **A device/sample-rate change goes through ONE hook, and a take never spans it** — `AudioEngine::handleStreamFormatChange` is called from BOTH `audioDeviceAboutToStart` and `prepareForHost`; a new prepare-path consumer must be added there, in order (transport first, so every later step and every module's next `processBlock` sees the new rate consistently), never duplicated per call site. `AudioClipStreamer::invalidateAllStreams()` is why a Track Audio ring can't just rely on its normal self-healing miss: a rate change is a *discontinuity* in `sourceFrame`'s mapping, so the new frame number could coincidentally land inside the OLD window and read back real-but-wrong-position audio instead of silence. An in-flight take (audio or MIDI) is finalized at the boundary, never continued: an audio take's WAV has a fixed header rate set at `startCapture()`, so recording across a rate change would silently mix two real rates under one declared one — `MainComponent::AudioTake` freezes `captureSampleRate`/`captureBpm`/`captureRecordingLatencySamples` at record-on for exactly this reason; reading them live at commit time (as older code did, safely, only because the rate never used to change mid-take) silently divides an OLD-rate sample count by a NEW-rate samples-per-beat. → [`docs/architecture.md`](docs/architecture.md)

Timeline + Per-Module Automation P7·1 · XL · client

Concept design & implementation plan · 2026-08-10 · planning artifact — the feature stays parked until after revenue; only Phase TL0 is do-now work. Derived from a 3-design / adversarial-critique planning pass over the actual codebase; every file:line claim below was spot-verified in source.

1 · The concept: the arrangement over the rack

In a normal DAW you double-click a track to reveal a hidden instrument. Here the instrument is already on screen — the graph is the rack — so the window splits: rack on top, arrangement below, and a track is not a container for an instrument, it is a feed into the rack. You look up, not in. That single reframing is the product story, and it is the thing Cubase structurally cannot copy.

Architecturally the timeline is a conductor, not a second engine. At audio time it does exactly two things the user already does by hand: inject MIDI into a graph node (play a keyboard) and move a parameter's base value (turn a knob). Nothing in the audio path gets new semantics, existing CV modulation stacks on top unchanged, and disabling the timeline leaves a fully working patch — which is what makes every phase independently shippable and revertible.

Five pillars covered by this plan: ① MIDI tracks → graph modules · ② hosted VST/AU modules · ③ hardware audio input through the graph · ④ recording graph output onto audio tracks · ⑤ Cubase-style automation (record + manual edit), with AI-authored arrangement as the end-game layer.

  • 1A track is a node. Creating a MIDI track creates a small, real, visible Track In node in the graph, named and coloured after the track. You see that Track 2 feeds the Diva VST because there is an ordinary purple MIDI cable from a node called "Track 2" — rendered, hit-tested and serialized like every other cable. No hidden side-channels.
  • 2External plugins are modules. A hosted VST/AU instrument or effect is one dashed-border node: patch MIDI in, patch audio out through the filter rack, open its native UI in a floating window. Its parameters become automatable lanes like any module's.
  • 3Hardware input is a module. Mic / analog synth comes in as an Audio In node you can route through any chain (input is off by default — monitoring only when a track is armed, with a feedback guard).
  • 4Record anywhere. A Rec Tap node captures any point of the graph — not just master — onto an audio track. Master output stays the one-click default.
  • 5Routing chip. The track header names its destination ("→ Poly MIDI"). Unbound tracks turn amber with one-click re-bind; deleting a module never silently deletes clips or automation (orphan, never delete).
  • 6Automation lanes, Cubase-style. Per-(module, parameter) lanes with Read / Touch / Latch / Write, recorded from real knob gestures (thinned on commit) or drawn with pencil / line / tension-drag tools. Right-click any knob in the rack → "Show automation lane". Automation moves the knob's base value; CV modulation keeps wobbling on top — the knob's ring shows the automated base, the arc shows CV depth.
  • 7Playhead. Sweeps only while the transport runs, repainting a confined strip — the second documented exception to the app's time-bounded-animation rule (same pattern as the AI spinner).
  • 8Audio clips stream from disk (recorded takes are not Sampler-style RAM loads), draw a live-growing waveform while recording, and land latency-compensated at the position you actually played.
Two view states: Split (default, above) and Arrange-Full, where the rack collapses to a thin rail — one shortcut, Ableton-Tab muscle memory. There is deliberately no tabbed mode: a user drawing a filter sweep must be able to see the filter. Fonts stay Inter + JetBrains Mono, colours resolve through one resolveTrackColour() (the resolveCableColour rule), and the whole panel is one new region in MainComponent::resized().

3 · Ten architecture decisions (and why)

Synthesized from three independently-generated designs + an adversarial critique. Spine: engine-first. Packaging: incremental. Identity & product framing: DAW-UX.

1 · Conductor, not engine. The timeline only injects MIDI and writes parameter base values. Removing it leaves a working patch; every phase is revertible. It ships behind SYNTH_ENABLE_TIMELINE with a CI job that builds+tests with the flag OFF — revertibility proven, not claimed.
2 · Real nodes, real cables. Track feeds, audio in, record taps and hosted plugins are ordinary ModuleBase nodes — routing, cable rendering, poly fan-out, serialization and undo come free. The existing ExternalMidiModule::pushMidiMessage back-channel (which stamps everything at sample 0) is explicitly the anti-pattern.
3 · Pull, don't push. Timeline source modules read an immutable TimelineSnapshot + per-block BlockTimeInfo and compute their own events — deterministic under seek/loop/tempo change, no cross-thread event queues, correct metadata.samplePosition on every note.
4 · One clock. TransportService in Core ticks once per audio callback before the graph runs. All time conversion goes through a two-method TempoMap seam (beatFromSample/sampleFromBeat) — constant BPM in v1, tempo maps later without touching lanes or clips. Beats are canonical; each track/lane carries timeBase: musical|linear. Existing Sequencer/PolySequencer keep their private BPM and gain an opt-in Sync to Transport (default off — presets stay byte-identical).
5 · Automation writes the base value. Verified: every module reads param->get() fresh per block and applies CV as an offset on top (OscillatorModule.h:329, AttenuverterModule.h:46). So automation = "someone turning the knob very precisely": param->setValue() per 64-sample slice — never setValueNotifyingHost on the audio thread — and zero per-module DSP changes. Zipper noise handled by slicing + a SmoothedValue audit enforced by a parameterised test (11 of ~21 modules smooth today).
6 · Snapshot/RCU handoff. Message thread edits TimelineDoc, publishes an immutable flattened snapshot via one atomic pointer; the audio thread loads it once per callback. Epoch-based reclamation (free after audioEpoch+2), zero allocation/locks/logging on the audio thread. Drags edit a preview overlay and publish on mouse-up.
7 · Identity = per-node uuid. Bindings and lanes must not key on the integer node id: merge-mode apply can silently alias ids (AIStateMapper.cpp:914-971). A stable uuid per node (honoured trusted-only, regenerated for untrusted input) is the identity everything keys on; unresolvable targets become orphaned, never deleted.
8 · Denormalized values + range snapshot. Lane points store natural units ("cutoff 200→8000 Hz") like params already does — human/AI-readable, validatable against the parameter's real range, immune to the untrusted [0,1] rescale heuristic. Each lane snapshots its range at author time so a later range change clamps detectably. (One-way door — flagged in §9.)
9 · Reserve exactly three schema things now. schemaVersion, nodes[].uuid, and timeline: z.unknown().optional() — one root key, shape deliberately undefined, refused (not ignored) on the untrusted path, kept out of getPatchSchema(), with an additive-only golden-schema CI gate. params stays a flat scalar map forever. Everything else (tempo, tracks, clips, lanes, assets) nests inside timeline later.
10 · Hard trust boundary. Hosted-plugin nodes and timeline data are trusted-path-only: untrusted provider output can never name a plugin binary, hand it a state blob, or smuggle automation (TimelineNotAllowed). isInternalOnlyModule's two-name check becomes an explicit authorable allowlist with a golden test, so registering a new module type never silently becomes model-authorable. Asset references are relative-inside-bundle only.

4 · What the code says today (verified during planning)

Found by the planning pass, spot-verified in source. The first three are live bugs worth fixing regardless of the timeline.

Live data-loss bug: getFactoryTypeName maps ModuleType::PolySequencer to "Sequencer" (AIStateMapper.cpp:504-505) while the factory registers "Poly Sequencer". Every save/load — and every structural undo, which replays the same JSON — silently downgrades a Poly Sequencer to a mono Sequencer. Fix now (TL0.8).
Undo rebuilds the world: every undo/redo replays the entire graph via applyJSONToGraph(clearExisting=true) under the audio callback lock (AppUndoManager.cpp:27,36). Fine for today's modules; fatal once hosted plugins exist (every Cmd+Z would re-instantiate every VST while holding the audio lock) and bad for timeline nodes mid-playback. A diffing/node-preserving restore is a hard prerequisite for plugin hosting (TL2.7).
Wall-clock on the audio thread: PolyMidiModule uses Time::getMillisecondCounter() for voice stealing and ignores velocity entirely (PolyMidiModule.h:150-151) — every offline/bounce render with polyphony is non-deterministic, and machine-generated MIDI exposes it (identical timestamps degenerate LRU; same-pitch retrigger produces no new gate edge).
PDC misconception
JUCE's graph already delay-compensates parallel paths internally. The real missing work: shift recorded audio back by device+graph latency, offset the drawn playhead by output latency, rebuild when a hosted plugin's latency changes.
Patch format
{nodes[{id,type,params,state?,position}], connections, modulations} + mode/remove/removeModulations. No version field. validatePatch never inspects unknown keys — and graphToJSON rebuilds from live state, so unknown keys are silently dropped on the next save. "Forward-compatible" requires the TL0 preservation work; it does not exist today.
Audio input
Hard-disabled: device opened with 0 inputs, callback ignores inputChannelData. Pillar ③ is greenfield and changes every user's persisted device state (migration task included).
No global clock
Sequencer and PolySequencer each own a private BPM parameter and count samples locally. External MIDI reaches the graph via two uncoordinated paths, one of which stamps events at sample 0.
Parameters
Hardcoded string paramIDs, stability by convention only; UI via stock JUCE attachments with begin/endChangeGesture (the automation-capture seam); undo is per-gesture whole-graph snapshots — an automation writer must bypass it or explode the 30 MB undo buffer.
Contracts package
synth-platform/packages/contracts was not found on this machine and the C++ getPatchSchema is hand-written — TL0.1 verifies whether the Zod→JSON-Schema→C++ codegen actually exists before any schema task is written against it.

5 · Milestones

TL0 · Format & identity do now

Schema reservation, node uuid, trust refusal, unknown-key preservation, 3 live-bug fixes. Zero UI. Ships alone; commits to nothing.

TL1–TL5 · Timeline v1

Transport spine → document/handoff → MIDI tracks → automation engine → UI. MIDI + full automation, no audio tracks. Each phase demoable.

TL6 · v1.5 Audio

Hardware input, recording to tracks, disk streaming, latency alignment, bounce polish.

TL7 · v2 Plugins

Hosted VST/AU/CLAP modules — gated on the licensing decision and the undo fix.

TL8 · Agentic

AI reads & writes the arrangement through its own validated capabilities — the "Agentic Audio Workstation" layer.

Size legend (agent-assisted work): S < ½ day · M 1–2 days · L 3–5 days · XL 1–2 weeks. Model legend: haiku mechanical, well-specified edits — these are also the only realistic local-model candidates; sonnet standard feature work with a clear spec; opus architecture, real-time audio, threading, schema/security surfaces. Real-time audio code should never go below sonnet.

4Automation value encodingDenormalized parameter units + per-lane range snapshot (recommended: matches params, AI-readable, dodges the rescale heuristic). This is a one-way door once files exist — the alternative (normalized 0..1) survives range widening but is opaque in files.

6Panel resizingFixed heights with presets is much cheaper; a drag splitter is genuinely new UI surface (none exists in the codebase). Recommend fixed for v1, splitter later.

9Sequencer clock long-termOpt-in sync keeps presets intact, but two clock concepts will eventually confuse users. Decide the end state now (default-on for new instances after v2?) even if migration waits.
